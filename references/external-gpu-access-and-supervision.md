# External GPU access detached render supervision Use this reference when Shorts render uses remote notebook runtime or when checking whether saved Kaggle connection can run job. ## Verify remote notebook before moving work 1. Check configured provider/runtime separately notebook-execution access; saved model-serving tunnel or provider endpoint proves only configuration was recorded, not GPU notebook can be controlled. 2. Check credential presence permissions without printing values: `test -f ~/.kaggle/kaggle.json && stat -c '%a %n' ~/.kaggle/kaggle.json`; parse only required key names, never echo JSON. 3. Check installed CLI generation `kaggle --version` `kaggle kernels --help`; use authentication format documented by installed version rather assuming legacy `username/key` credentials accepted. 4. Validate access harmless authenticated account/notebook-list request before uploading inputs scheduling GPU work. Treat HTTP 401 as unverified access; do not retry by exposing credentials or inventing alternate auth. 5. Only after authentication succeeds, confirm notebook ownership, GPU availability, execution mechanism. Do not infer saved credentials, old tunnel URL, or memory note. ## Kaggle batch GPU execution and output extraction 1. Never rely on in-kernel downloads from ephemeral or CDN/signed URLs; download sources locally and upload to a Kaggle private dataset (`kaggle datasets create -p <dir>`) so kernel inputs remain reproducible and immune to 403 blocks. 2. Push script kernels with `enable_gpu: true` in metadata, specify input dataset slugs under `dataset_sources`, and monitor with `kaggle kernels status <slug>` rather than running long blocking tasks. 3. Download outputs with exact patterns (`kaggle kernels output <slug> -p <dir> --file-pattern ".*\.mp4"`) to avoid pulling massive transient checkpoint or cache directories. Clean local background supervision processes once complete.
4. Supervise detached Kaggle runs proactively via scheduled Gateway automation: when launching or supervising an asynchronous Kaggle run (`kaggle kernels push`), register an automation (`automations(action="add")`) with `{schedule: {kind: "every", everyMs: 300000}}` (5m interval) that checks `kaggle kernels status <slug>`, downloads and delivers the artifact on completion, reports failure logs on error, and removes the scheduled job. Never claim or promise "I am monitoring" without an active scheduled automation, because assistant sessions sleep between inbound turns. ## Supervise detached Colab worker 1. Before starting resuming, inspect session identity/status, worker PID, child process tree, status JSON, outputs, recent logs. Do not launch second writer while worker or child still exists. 2. Treat Colab's `IDLE` label notebook front end's execution state, not proof detached subprocess is gone; inspect remotely `ps -ef` verify worker/child PIDs. 3. Distinguish heartbeat/status JSON actual stage progress. If status static, read inference tool's recent progress log process CPU activity; report observed completed/total frames timestamp, not stale percentage. 4. Estimate remaining time only recent measured throughput remaining units, label it approximate; report later encode verification remaining stages. 5. Confirm completion only when media/decode/audio GPU or terminal failure confirmed.
